# 动态物体处理工程归档

本文归档当前对动态物体处理链路的追踪结果，范围覆盖 `loader/`、`pre_train/`、`train/` 和导出阶段。结论先写：

- 动态物体采用“局部几何 + 每帧位姿”的设计：`meta_data.verts` 保存每个动态物体局部 bbox 顶点，`meta_data.frames[*].dynamics` 保存该物体在当前帧 ego 坐标下的位姿。
- `pre_train/create_dynamic_mask.py` 生成的 `masks/*.npy` 是静态可用像素掩码，不是动态物体掩码。
- 动态 mask 当前采用 `动态语义像素 ∩ 3D bbox 投影区域`，是偏保守的高精度、低召回策略；对语义误检有一定防御，对 bbox/标定偏移比较敏感。
- `points3d.ply` 通过 `masks/*.npy` 排除动态物体区域，背景点云不主动包含动态物体。
- 当前语义 id 使用 Cityscapes trainId：`0=road`、`1=sidewalk`、`10=sky`。`merge_depth_wo_ground.py` 的 `semantics > 1` 会把 sky 纳入非地面候选，代码没有显式排除 sky。
- `train_ground.py` 以 `ignore_dynamic=True` 读取数据，只训练地面；`train_scene.py` 才初始化并优化动态物体 Gaussian。
- 动态 Gaussian 保存在物体局部坐标中，渲染时按当前帧物体 world 位姿变换到世界坐标，再和背景 Gaussian 拼接后一起 rasterize。
- 当前动态 Gaussian 有 optimizer step，但 densify/prune/reset 逻辑处于注释状态。

## Loader 输出契约

统一 loader 输出中的动态物体字段分为两类：

```json
{
  "verts": {
    "track_id": [[x, y, z], "... 8 个局部 bbox 顶点"]
  },
  "frames": [
    {
      "ego_to_world": [[...], [...], [...], [...]],
      "dynamics": {
        "track_id": {
          "object_to_ego": [[...], [...], [...], [...]]
        }
      }
    }
  ]
}
```

`verts[track_id]` 是物体自身坐标系下的 8 个 bbox 顶点，只表达尺寸和局部形状；它不表达某一帧物体在哪里。

`frames[*].dynamics[track_id].object_to_ego` 是该物体局部坐标到当前帧 ego 坐标的 4x4 变换。下游使用同一套公式：

$$
T_{\text{object}\rightarrow\text{camera}}
= T_{\text{camera}\rightarrow\text{ego}}^{-1}
  T_{\text{object}\rightarrow\text{ego}}
$$

$$
T_{\text{object}\rightarrow\text{world}}
= T_{\text{ego}\rightarrow\text{world}}
  T_{\text{object}\rightarrow\text{ego}}
$$

因此，`verts` 和 `object_to_ego` 是配套字段。只有 `object_to_ego` 时知道位姿但不知道尺寸；只有 `verts` 时知道尺寸但不知道当前帧位置。

## Loader 阶段

`loader/` 负责从原始数据集标注中筛选动态物体，写入统一 schema，并生成 `box/` 调试图。

Waymo：

- 从 `laser_labels` 中读取 `VEHICLE`、`PEDESTRIAN`、`CYCLIST`。
- 每个标注生成 `object_to_ego`，旋转来自 box heading，平移来自 box center。
- 用全局中心轨迹筛选真正移动的物体，当前阈值是 `movement > 1`。
- 用 `get_vertices(dims)` 生成 8 个局部 bbox 顶点。
- 只把相机中可见的动态物体帧写入 `frames[*].dynamics`，只把序列中至少可见一次的动态物体写入 `verts`。

关键位置：

- `loader/waymo/load.py:get_vertices`
- `loader/waymo/load.py` 中 `vehicles`、`dynamics`、`verts`、`rts` 的生成逻辑
- `loader/waymo/load.py` 写 `meta_data["frames"][*]["dynamics"]`

NuScenes：

- 以 `instance_token` 作为 track id。
- 汇总每个 instance 的 annotation 轨迹。
- 当前用首尾位移条件筛选动态物体，阈值是 `> 2`。
- 每帧先得到 `object_to_global`，再按当前相机曝光时刻的 ego pose 转成 `object_to_ego`：

$$
T_{\text{object}\rightarrow\text{ego}}
= T_{\text{global}\rightarrow\text{ego}}
  T_{\text{object}\rightarrow\text{global}}
$$

关键位置：

- `loader/nuscenes/load.py` 中 `tracks`、`dynamic_instance` 的生成逻辑
- `loader/nuscenes/load.py` 写 `meta_data["verts"]`
- `loader/nuscenes/load.py` 写每个相机 frame 的 `frame_dynamics`

PandaSet：

- 从 cuboids 中选择 `~stationary` 且类别属于动态类的目标。
- 动态类由 `ALLOWED_RIGID_CLASSES + ALLOWED_NONRIGID_CLASSES` 构成。
- cuboid pose 先在 PandaSet native global 下构造，再用当前 lidar ego pose 转到 native ego，最后乘固定轴变换转到 HUGSIM ego：

$$
T_{\text{object}\rightarrow\text{ego}}
= C_{\text{pandaset native}\rightarrow\text{hugsim ego}}
  T_{\text{global}\rightarrow\text{ego native}}
  T_{\text{object}\rightarrow\text{global}}
$$

- 同一帧的动态物体 pose 写入该帧所有相机条目。

关键位置：

- `loader/pandaset/pandaset_utils.py:get_vertices`
- `loader/pandaset/load.py` 中 `valid_mask`、`cuboid_poses`、`frame_dynamic_boxes`
- `loader/pandaset/load.py` 写每个相机 frame 的 `dynamics`

调试图：

`loader/common.py:draw_dynamic_boxes` 负责把 `verts + object_to_ego` 投影到图像，并在 `box/` 下画 3D bbox。这个产物用于检查动态框与相机标定/位姿是否一致，不直接参与训练。

## Pre Train 阶段

`pre_train/run_prepare.py` 的默认顺序是：

```text
infer_semantics.py
create_dynamic_mask.py
estimate_depth.py
merge_depth_wo_ground.py
merge_depth_ground.py
```

动态物体主要在 `create_dynamic_mask.py` 和 `merge_depth_wo_ground.py` 中影响训练前产物。

### 动态 mask 生成

`pre_train/create_dynamic_mask.py` 读取：

- `meta_data.json`
- `camera_paras.json`
- `semantics/*.npy`

每帧处理逻辑：

1. 读取该图像的语义分割结果。
2. 用 `DYNAMIC_SEMANTIC_IDS = (11, 12, 13, 14, 15, 18)` 得到动态语义像素。
3. 遍历 `frame["dynamics"]`。
4. 如果该 `object_id` 不在 `verts` 中，跳过。
5. 用 `camera_to_ego`、`object_to_ego`、`verts[object_id]` 投影 3D bbox。
6. 填充 bbox 六个面得到 `bbox_mask`。
7. 只把 `bbox_mask` 和动态语义像素的交集记为动态区域。
8. 保存 `static_mask = ~dynamic_mask`。

输出含义：

```text
masks/*.npy == True  表示静态可用像素
masks/*.npy == False 表示动态物体区域
```

这是最容易误读的点。文件名叫 `masks`，但训练前合并点云和训练 loss 中使用的是“可用静态区域”。

### 动态 mask 交集策略

设：

```text
S = 语义分割认为是动态类别的像素
B = 已跟踪动态物体 3D bbox 的图像投影区域
```

当前实现等价于：

```text
dynamic_mask = S ∩ B
static_mask = ~dynamic_mask
```

这里的 `DYNAMIC_SEMANTIC_IDS = (11, 12, 13, 14, 15, 18)` 对应 Cityscapes trainId 中的 `person`、`rider`、`car`、`truck`、`bus`、`bicycle`。

取交集的目的不是认为语义像素必然是 bbox 的子集，而是让 2D 语义和 3D 跟踪互相约束：

- 只用 `S` 会删除所有被分成车、人、骑行者的像素，包括静止车辆、未跟踪目标和语义误检区域。
- 只用 `B` 会删除 3D bbox 投影中的路面、背景、遮挡空隙和非物体像素。
- 用 `S ∩ B` 只删除“有动态 track 支持，并且像素也像动态类别”的区域。

这个策略偏保守。它的收益是少误删静态背景，代价是只要语义或 bbox 任一侧漏掉，动态物体就会残留。

`object_id not in verts` 在正常统一 loader 输出中理论上不应发生，因为能写入 `frames[*].dynamics` 的动态物体应有对应 `verts`。保留这个判断是防御旧格式、手工修改、id 类型不一致或中间文件不完整。缺 `verts` 时无法知道物体尺寸，无法投影 bbox，只能跳过。

“填充 bbox 六个面”是把 8 个 3D 角点投影成图像上的区域 mask。只连 bbox 边只能得到线框，不能用于像素级过滤；`cv2.fillPoly()` 把 3D box 的 6 个面投影后填满，得到粗略的 2D 占据区域 `bbox_mask`。这个区域不是精确物体轮廓，后续还要和语义分割取交集。

### 语义和 bbox 误差组合

当前策略对不同误差的表现如下：

| 情况 | `S ∩ B` 结果 | 主要风险 |
| --- | --- | --- |
| 语义准，bbox/标定准 | 最理想，真实动态物体被删，bbox 内背景由语义过滤保留 | 基本无问题 |
| 语义不准，bbox/标定准 | bbox 限定误删范围，但语义漏检会残留动态物体 | 语义漏检导致动态残影；bbox 内语义误检导致局部误删 |
| 语义准，bbox/标定不准 | 语义能防止大面积误删，但 bbox 偏移会让交集变小 | 标定偏移、bbox 偏小或 pose 不准导致动态物体删不干净 |
| 语义不准，bbox/标定不准 | 结果不可控，通常更偏向漏删 | 同时出现动态残留和静态误删 |

现有代码的防御主要是：

- 缺 `verts` 跳过，避免程序崩溃。
- 投影深度、除零、非有限值、坐标爆炸时跳过。
- 用 `S ∩ B` 限制误删范围。
- loader 侧只写入可见动态物体，过滤完全不可见目标。

这些防御对语义误检比较有效，但对 bbox/标定偏移不够友好。标定偏移时，真实动态语义像素可能落在 `B` 外，导致动态物体残留进 `points3d.ply`。如果标定经常不准，更稳的改法通常是先膨胀 bbox 投影区域，再和语义取交集：

```text
dynamic_mask = dilate(B, r) ∩ S
```

其中 `r` 可做成参数，例如 `--bbox_dilate 0/5/10/20`。代价是语义误检多时会多删 bbox 周边静态区域。工程上也建议额外输出 `dynamic_semantics.png`、`bbox_mask.png`、`dynamic_intersection.png`、`static_mask.png` 之类调试图，快速区分语义错、标定错还是两者都错。

### 背景点云合并

`pre_train/merge_depth_wo_ground.py` 负责生成 `points3d.ply`。它读取每帧：

- RGB 图像
- depth
- semantics
- masks

有效点条件是：

```python
valid_mask = static_mask & semantic_mask & finite_depth
```

其中 `semantic_mask = semantics > 1`，即非地面语义；`static_mask` 来自 `masks/*.npy`。所以动态 bbox 和动态语义交集内的像素不会进入 `points3d.ply`。

`pre_train/merge_depth_ground.py` 负责生成 `ground_points3d.ply` 和 `ground_param.pkl`。它只使用 `semantics <= 1` 的地面像素，不依赖动态 bbox。

这里实际是在生成两份不同用途的点云：

```text
ground_points3d.ply = 地面点云
points3d.ply = 非地面、静态背景点云
```

`ground_points3d.ply` 后续由 `train_ground.py` 初始化地面 Gaussian；`points3d.ply` 后续由 `train_scene.py` 初始化非地面背景 Gaussian。动态物体不从这两份 depth 点云初始化，而是由 `verts` 缩放车辆模板后初始化 `ObjModel`。

`merge_depth_wo_ground.py` 的有效点条件可以拆成：

```text
static_mask: 不在动态排除区域内
semantic_mask: 不是 road/sidewalk
finite_depth: 反投影后的 3D 点为有限值
```

因此 `points3d.ply` 的语义是：

```text
深度有效 + 非 road/sidewalk + 静态可用区域
```

当前语义分割输出是 Cityscapes trainId：

```text
0 = road
1 = sidewalk
2 = building
...
10 = sky
11 = person
12 = rider
13 = car
14 = truck
15 = bus
18 = bicycle
```

所以 `semantics <= 1` 不是“地面 id 为 1”，而是把 `road` 和 `sidewalk` 都当作地面/近地平面类。`semantics > 1` 表示非 road/sidewalk 候选。

需要注意的是，`sky=10` 也满足 `semantics > 1`。当前代码没有显式排除 sky，只用 `np.isfinite(local_points).all(axis=1)` 检查深度反投影是否有限。UniDepth 输出的 sky 深度不一定是 `inf` 或 `nan`；如果它给 sky 预测了有限深度，sky 像素可能进入 `points3d.ply`。更稳的过滤方式是显式排除 sky，并可选增加深度范围：

```python
semantics = np.load(semantics_path).reshape(-1)
depth_flat = depth.reshape(-1)
semantic_mask = (semantics > 1) & (semantics != 10)
valid_depth = np.isfinite(local_points).all(axis=1) & (depth_flat > 0) & (depth_flat < max_depth)
valid_mask = static_mask & semantic_mask & valid_depth
```

`merge_depth_ground.py` 不使用动态 bbox。它只取 `semantics <= 1` 的像素做地面点云。正常情况下车、人不会被语义分成 road/sidewalk，因此不需要动态 bbox；如果语义把车身误分成地面，当前地面点云也会被污染，代码没有额外防御。

### 缺字段影响

如果 `meta_data.verts` 缺失，或者某帧 `dynamics` 中的 `object_id` 不在 `verts` 内，`create_dynamic_mask.py` 会跳过该物体。结果是该物体区域不会被 bbox 逻辑排除，后续可能被合进背景 `points3d.ply`。

如果 `frames[*].dynamics` 缺失，`verts` 即使存在也无法投影到具体帧，同样不会生成动态排除区域。

## Train 阶段

训练入口分两步：

```text
train/train_ground.py
train/train_scene.py
```

`train/run_reconstruction.py` 按上述顺序调用它们。

### 数据读取

`scene/dataset_readers.py` 读取统一 loader schema：

- `meta_data.verts` 被转成 `scene_info.verts`。
- 每帧 `object_to_ego` 被转成 `object_to_world`。
- 转换后的 world pose 放到 `CameraInfo.dynamics`，再进入 `Camera.dynamics`。

转换公式：

$$
T_{\text{object}\rightarrow\text{world}}
= T_{\text{ego}\rightarrow\text{world}}
  T_{\text{object}\rightarrow\text{ego}}
$$

`Camera.dynamics` 中保存的已经是 world pose，渲染侧把它作为 `B2W` 使用。

### 地面训练

`train/train_ground.py` 调用：

```python
load_cameras(cfg, True)
```

这里 `ignore_dynamic=True`，读取相机时不加载动态物体，也不会创建动态 Gaussian。地面训练只用 `ground_points3d.ply` 初始化地面 Gaussian，并用 `semantics <= 1` 约束地面区域。

### 完整场景训练

`train/train_scene.py` 创建：

- 背景 `GaussianModel`
- 每个动态物体一个 `ObjModel`

`Scene` 初始化动态物体的逻辑：

1. 遍历 `scene_info.verts`。
2. 每个 track 创建一个 `ObjModel`。
3. 读取统一车辆模板 `utils/vehicle_template/benz_nuscenes.ply`。
4. 根据 `verts` 的 bbox 范围计算长宽高。
5. 用 bbox 尺寸缩放车辆模板点云。
6. 调用 `dynamic_gaussian.create_from_pcd()` 初始化物体局部 Gaussian。

当前 `ObjModel(feat_mutable=False)` 时，动态物体的 3D semantic feature 固定为第 13 类。它不是从当前物体类别细分出来的，而是统一按动态车辆模板处理。

### 渲染中的动态物体

`gaussian_renderer.render()` 中，动态物体处理流程是：

1. 默认从 `viewpoint.dynamics` 读取每个 track 的 `B2W`。
2. 如果启用 unicycle，则用 unicycle 模型在当前 timestamp 预测 `B2W`。
3. 读取该 track 的局部动态 Gaussian：`dynamic_gaussian.get_xyz`、opacity、scale、rotation、features。
4. 用 `B2W` 把局部点变换到 world：

$$
\mathbf{x}_{world}
= R_{B2W}\mathbf{x}_{local} + \mathbf{t}_{B2W}
$$

5. 用 `B2W` 左乘局部旋转，得到 world rotation。
6. 把所有动态 Gaussian 和背景 Gaussian 拼接。
7. 统一调用 gsplat rasterization。

这意味着动态物体本体参数是在局部坐标中学习的；每帧运动由 `Camera.dynamics` 或 unicycle 模型提供。

### Loss 和 mask

`train/train_scene.py` 中 `cfg.ignore_dynamic` 控制是否在 loss 中忽略动态像素：

- `ignore_dynamic=False`：默认值，动态区域也参与 RGB/semantic loss，动态 Gaussian 会被图像监督。
- `ignore_dynamic=True`：使用 `masks/*.npy` 把动态区域从 gt 中替换为当前 render 的 detach 值，相当于不对动态像素施加 RGB/semantic 监督。

因此，`masks/*.npy` 在 pre_train 中用于剔除背景点云动态区域，在 train 中只有 `cfg.ignore_dynamic=True` 时才用于忽略动态区域 loss。

### 优化和 densification

`train/train_scene.py` 中背景 Gaussian 和每个动态 `ObjModel` 都执行：

```python
optimizer.step()
optimizer.zero_grad()
```

当前动态 Gaussian 的 densification 状态：

- 会对当前 viewpoint 中出现的动态 track 收集 viewspace gradient stats。
- 真正的 `dynamic_gaussian.densify_and_prune()` 被注释。
- `dynamic_gaussian.reset_opacity()` 也被注释。

结果是动态物体点数主要来自初始化车辆模板，训练中不会像背景一样主动增删点。

## Unicycle 模型

`cfg.unicycle=True` 时，`train/dynamic_utils.py:create_unicycle_model()` 会从训练相机中筛选 `CAM_FRONT`，按 timestamp 汇总每个 track 的 world pose。

它提取：

- 平面中心 `b2w[[0, 2], 3]`
- 高度 `b2w[1, 3]`
- 欧拉角

然后拟合一个简化车辆运动模型。渲染时不再直接使用 `viewpoint.dynamics[track_id]`，而是用 `unicycle_b2w(timestamp, model)` 预测该时刻的 `B2W`。

`uc_opt_pos=True` 时，unicycle 的位置参数也进入优化；否则主要优化速度和 yaw。

## Checkpoint 和导出

`train/train_scene.py` 保存：

```text
ckpts/chkpnt{iteration}.pth
ckpts/dynamic_{track_id}_chkpnt{iteration}.pth
ckpts/unicycle_{track_id}.pth
```

`eval_render/export_scene.py` 导出时：

- 把 `ckpts/chkpnt{iteration}.pth` 复制为 `scene.pth`。
- 把 `ckpts/dynamic_{track_id}_chkpnt{iteration}.pth` 复制为 `dynamic_{track_id}.pth`。
- 复制 `unicycle_*.pth`。
- 复制 `meta_data.json`、`camera_paras.json`、`geo_reference.json`。

导出后的动态物体仍然依赖：

- `dynamic_{track_id}.pth`：局部动态 Gaussian。
- `meta_data.json` 或 scenario/planner：提供物体轨迹或规划位姿。
- `unicycle_{track_id}.pth`：可选轨迹模型。

## 易错点

- `verts` 是局部 bbox 顶点，不是 world 顶点，也不是每帧位置。
- `frames[*].dynamics[*].object_to_ego` 是每帧位姿，不包含尺寸。
- `masks/*.npy` 的 `True` 表示静态可用区域，`False` 表示动态排除区域。
- 动态 mask 不是纯语义分割结果，而是 `3D bbox 投影` 和 `动态语义像素` 的交集。
- `semantics <= 1` 表示 Cityscapes trainId 中的 `road + sidewalk`，不是单独的“地面 id=1”。
- `semantics > 1` 会包含 `sky=10`；当前 `points3d.ply` 生成没有显式排除 sky，有限深度预测可能让天空点进入背景点云。
- 当前动态 mask 策略对语义误检较保守，对 bbox/标定偏移较敏感；标定偏移时容易漏删动态物体。
- 默认 `ignore_dynamic=False` 时，训练 loss 不会忽略动态区域。
- 动态 Gaussian 当前不会 densify/prune，点数主要由车辆模板初始化决定。
- 如果 loader 没写好 `verts` 或 `dynamics`，动态物体可能被错误合入背景点云，后续训练会把它当静态背景处理。
