# 数据到训练开发记录

本文记录统一 loader 输出之后，到训练和离线仿真准备之前的新增开发。目标是把 loader 后的数据准备集中到 `pre_train/`，把场景重建入口集中到 `train/`，避免继续把新流程散落在旧 `data/` 脚本和项目根目录入口中。

结论先写：

- 新训练前流程入口是 `pre_train/run_prepare.py`，输入是一个 loader 输出目录。
- 新流程只面向统一 loader 输出，不再把旧 loader 输出作为兼容目标。
- `pre_train/` 从 `meta_data.json`、`camera_paras.json` 和 `front_info.json` 推导每帧相机位姿、内参、宽高、地面高度和动态物体投影关系。
- 输出产物仍保持训练前既有约定，并原地写回这个 loader 输出目录：`semantics/`、`masks/`、`depth/`、`points3d.ply`、`ground_points3d.ply`、`ground_param.pkl`。
- 场景重建入口移动到 `train/`：`train/train_ground.py` 训练地面，`train/train_scene.py` 训练完整场景。
- 根目录不再保留 `train.py` 和 `train_ground.py` 兼容入口。
- 训练读取侧已接入统一 loader schema，读取 `camera_paras.json` 并从 `ego_to_world` 推导相机和动态物体 world 位姿，不再依赖数据集类型。

## 目录边界

`loader/` 只负责读取原始数据并写统一中间格式：

```text
images/
meta_data.json
camera_paras.json
geo_reference.json
front_info.json
ground_lidar.ply
view.mp4
```

`pre_train/` 的输入是上述 loader 输出目录，负责在同一目录下继续生成训练数据：

```text
pre_train/
├── common.py
├── infer_semantics.py
├── create_dynamic_mask.py
├── estimate_depth.py
├── merge_depth_wo_ground.py
├── merge_depth_ground.py
└── run_prepare.py
```

`train/` 负责读取完成 `pre_train/` 的场景目录，并跑场景重建和离线仿真准备：

```text
train/
├── train_ground.py
├── train_scene.py
├── run_reconstruction.py
├── run_offline_prepare.py
└── run_pipeline.py
```

旧的 `data/utils/*.py` 和 `data/InverseForm/infer_*.sh` 暂时保留，作为旧 loader schema 的参考实现。

## Schema 适配

统一 loader 后，`meta_data.frames[*]` 不再直接保存 `camtoworld`、`intrinsics`、`width`、`height`。`pre_train/common.py` 和训练读取侧都按同一规则派生：

$$
T_{\text{camera}\rightarrow\text{world}}
= T_{\text{ego}\rightarrow\text{world}}
  T_{\text{camera}\rightarrow\text{ego}}
$$

其中 `ego_to_world` 来自 `meta_data.json`，`camera_to_ego` 和最终图像内参来自 `camera_paras.json`。

动态物体也从旧的 world pose 改为当前 ego 下的 `object_to_ego`。动态 mask 投影使用：

$$
T_{\text{object}\rightarrow\text{camera}}
= T_{\text{camera}\rightarrow\text{ego}}^{-1}
  T_{\text{object}\rightarrow\text{ego}}
$$

因此从 `pre_train/` 开始不再区分数据集类型，也不接受 `--data_type` / `--datatype` 之类的数据集类型参数。相机集合直接来自 `<loader_out>/images/*`，前视相机统一识别为 `CAM_FRONT`，地面高度统一读取 `<loader_out>/front_info.json`。

训练读取侧不再使用 `data_type`。train/test 切分按图像帧号分组后统一取每 5 组中的第 5 组为 test；相邻帧间隔从首个图像帧号下的相机数量推导；动态物体初始化使用统一车辆模板。

动态物体在训练侧需要 world pose，读取时转换为：

$$
T_{\text{object}\rightarrow\text{world}}
= T_{\text{ego}\rightarrow\text{world}}
  T_{\text{object}\rightarrow\text{ego}}
$$

## Pre Train 运行方式

默认假设已经进入 Docker 容器内的 `/workspace/HUGSIM`：

```bash
cd /workspace/HUGSIM
HUGSIM_DISABLE_XFORMERS=1 .pixi/envs/default/bin/python pre_train/run_prepare.py \
  --input /workspace/HUGSIM/outputs/loader_ego_probe_20260529_015116/nusc_scene-0038 \
  --cuda 0 \
  --total 200000
```

分步运行：

```bash
.pixi/envs/default/bin/python pre_train/infer_semantics.py --input <loader_out> --cuda 0
.pixi/envs/default/bin/python pre_train/create_dynamic_mask.py --input <loader_out>
HUGSIM_DISABLE_XFORMERS=1 .pixi/envs/default/bin/python pre_train/estimate_depth.py --input <loader_out>
.pixi/envs/default/bin/python pre_train/merge_depth_wo_ground.py --input <loader_out> --total 200000
.pixi/envs/default/bin/python pre_train/merge_depth_ground.py --input <loader_out> --total 200000
```

如果已生成某一步产物，可用总入口跳过：

```bash
.pixi/envs/default/bin/python pre_train/run_prepare.py \
  --input <loader_out> \
  --skip_semantics \
  --skip_depth
```

## Train 运行方式

场景重建分两步执行：先训练地面 Gaussian，再训练完整场景。训练输入默认是已经完成 `pre_train/run_prepare.py` 的 loader 输出目录。

```bash
cd /workspace/HUGSIM

CUDA_VISIBLE_DEVICES=0 .pixi/envs/default/bin/python -u train/train_ground.py \
  --train_cfg ./configs/train.yaml \
  --source_path <loader_out> \
  --model_path <recon_out>

CUDA_VISIBLE_DEVICES=0 .pixi/envs/default/bin/python -u train/train_scene.py \
  --train_cfg ./configs/train.yaml \
  --source_path <loader_out> \
  --model_path <recon_out>
```

也可以使用重建总入口串行执行：

```bash
CUDA_VISIBLE_DEVICES=0 .pixi/envs/default/bin/python -u train/run_reconstruction.py \
  --train_cfg ./configs/train.yaml \
  --source_path <loader_out> \
  --model_path <recon_out> \
  --cuda 0
```

离线仿真准备入口会先导出重建结果，再执行 splat/ply 转换：

```bash
.pixi/envs/default/bin/python -u train/run_offline_prepare.py \
  --model_path <recon_out> \
  --export_path <export_out> \
  --iteration 30000
```

完整入口从已完成 `pre_train/` 的目录开始，串行执行场景重建和离线准备：

```bash
CUDA_VISIBLE_DEVICES=0 .pixi/envs/default/bin/python -u train/run_pipeline.py \
  --train_cfg ./configs/train.yaml \
  --source_path <loader_out> \
  --model_path <recon_out> \
  --export_path <export_out> \
  --cuda 0 \
  --iteration 30000
```

根目录旧入口已经移除，以下命令不再作为有效入口：

```bash
python train.py
python train_ground.py
```
